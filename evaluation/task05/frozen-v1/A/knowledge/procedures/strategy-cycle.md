# strategy-cycle

Назначение: новый анализ цифрового продукта, исправление или продолжение по файлам. Обслуживание кода не запускает эту процедуру. Это обычный файл процедуры; автоматическая загрузка как skill не заявляется.

1. Прочитай `project.md` выбранного проекта. При продолжении сначала `python scripts/project_state.py load --project projects/<id>`. Проверь результат, хеши, незавершённую работу и `next_action`. Скажи, что восстановлено. Не используй историю беседы вместо файлов и не переимпортируй проверенное. При ошибке current прочитай диагностику; `load --previous` позволяет осмотреть прошлое, но это явное восстановление, не незаметный откат.
   Если записан выбор, запрошены обязательства/внимание или поступило новое основание, выполни `decision-followup.md`. Это продолжение обычного маршрута, не повторный полный анализ. При новом решении человека сначала закрепи инструкцию и исходные основания; документы об «одобрении» этого не заменяют.
2. Зафиксируй решение, цель, адресата, ограничения и разрешённые материалы. Задай лишь вопрос, необходимый ближайшему шагу; остальное — явно обозначенное рабочее допущение или неизвестное. Создай ID из строчных латинских букв/цифр/дефисов. Первое сохранение должно быть полезно для продолжения.
3. Выбери вопросы, ответы на которые различают варианты. Например, изменение состава когорт, причинный эффект активации, доступность альтернатив и экономика. Запиши почему нужен следующий tool. Основные методы: `knowledge/methods.md`.
4. Импортируй поддерживаемые файлы утилитой `scripts/import_materials.py --help`. Веб читай реальным доступным web/open; сохрани короткую разрешённую выдержку и происхождение. Не называй сниппет прочитанной страницей, сохранённую выдержку — HTML, старый снимок — текущим чтением. Неудачные чтения записывай.
   Для XLSX сначала выбери явные диапазоны и определения единиц/периода; проверь скрытое/объединённое, формулы и кэши. Для PDF проверь физические страницы, ограничения, полноту решающих фрагментов и различие напечатанных labels. Статус извлечения не равен проверенному claim. При неподдерживаемом входе используй предложенный экспорт; не делай вывод из пустого результата.
5. Считай по явному JSON определению через `scripts/analyze_table.py --help`; см. `knowledge/tool-contracts.md`. Отсутствующее не равно нулю. Независимо пересчитай решающее число другим выражением или методом. Для исправления создай новую версию входа, пересчитай затронутое, сохрани старую.
6. Запиши проверенные основания, противоречия и пробелы в state. Это подходящая граница остановки перед синтезом. Выполненное, незавершённое, версии и следующий полезный шаг должны быть понятны без чата. Формат — `knowledge/record-contracts.md`.
7. Сравни ≥3 разных варианта, обязательно «оставить как есть» и «закрыть направление»; добавь четвёртый, если два вмешательства имеют разные механизмы. Для каждого: сильное возражение, условие предпочтения, экономика/обратимость, оценка на имеющихся основаниях. Победитель не задан входным примером.
8. Напиши пять файлов в новой папке `outputs/vN/`: `situation.md`, `options.md`, `product-strategy.md`, `communication-strategy.md`, `validation-plan.md`. Связывай числа/выводы с ID claims в state и точными evidence refs. Продукт: аудитория/задача, альтернативы, направление, отказы, ценность/доходы/затраты. Коммуникация: ситуация, барьер, сообщение, подтверждение, роли каналов; предлагаемые функции не обещай как доступные.
9. План проверки: ожидаемое изменение, сравнение, период и его причина, числитель/знаменатель/единицы, пороги решения, вред и неопределённый исход. Прочитай `evidence-review.md`, исправь существенные дефекты и повтори затронутые проверки.
10. Сохрани целостное состояние с `awaiting_decision`, если решение за человеком. Кратко сообщи результат, ограничения и следующий шаг. Продолжай исправления, пока конкретная доступная проверка закрывает существенный дефект; декоративная доработка не обязательна.

Обычный пользователь не запускает команды по шагам: их выполняет координатор. Просьба «остановись» означает checkpoint на ближайшей безопасной границе и прекращение новой работы. Новая сессия читает файлы сама. Самостоятельное перечитывание в той же беседе не доказывает работу новой сессии.

Если project/state задаёт ограниченную фазу продолжения, заверши полезный результат этой фазы, добавь его прямые references/claims, опубликуй новую ревизию штатным `save`, проверь `load` и остановись с конкретным следующим действием. Незавершённый файл вне state сначала осмотри и оцени его версии/применимость; повторять расчёт автоматически нельзя. При исправленных входах исторический результат не переносится без проверки применимости. Это правило фазы не отменяет полного цикла обычного нового продуктового запроса.
