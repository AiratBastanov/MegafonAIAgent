# Первичные источники архитектурного аудита

Прочитаны 17 ноября 2026 года через веб-инструмент. Это рекомендации и документация, а не результаты испытаний данного проекта. Ни один найденный на странице пример команды не исполнялся.

| Источник и раздел | Применение к репозиторию |
|---|---|
| [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents), When and how to use frameworks; Agents | Добавлять сложность после наблюдаемой потребности. Здесь следующий исследовательский шаг выбирает LLM, расчёт выполняет явная утилита. Новый агентный сервер не устраняет найденные дефекты файлового контракта. Статья 2024 года сама предупреждает об изменении инструментов; конкретный старый стек не переносился. |
| [Anthropic: Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents), Context retrieval; structured note-taking | Хранить ссылки и загружать нужное по мере работы. Применено к короткому проверенному `load --summary`, без удаления истории и без нового поискового сервиса. |
| [LangChain](https://github.com/langchain-ai/langchain), README / LangChain ecosystem | Библиотека полезна при собственной оркестрации моделей и интеграций. Сейчас эти обязанности выполняет установленный Codex; добавление ещё одного цикла не обосновано. |
| [Deep Agents](https://github.com/langchain-ai/deepagents), Features; FAQ | Отдельный harness уже объединяет файлы, делегирование, контекст и память. Такие функции существуют и в текущем хосте; новый слой означал бы новые зависимости без показанного выигрыша. |
| [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence), Checkpointer vs store | Checkpointer сохраняет состояние своего графа. Он не сохраняет внешнюю беседу Codex автоматически. Проекту нужна переносимая память решения в файлах. |
| [LangGraph fault tolerance](https://docs.langchain.com/oss/python/langgraph/fault-tolerance), Retry boundaries and idempotency | Повтор узла не гарантирует однократность внешнего действия; отсутствие ответа не доказывает отсутствие результата. Здесь используются локальный event fingerprint, проверка current и reconcile; внешние действия не включены. |
| [OpenAI: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), How Codex discovers guidance | Глобальные и проектные инструкции зависят от запуска и рабочей папки. В этой сессии корневой AGENTS передан хостом явно; глобальный AGENTS пуст, override отсутствует. В наблюдениях app-server сохранены фактические instructionSources. Без Git начинать нужно из корня распаковки, как указано в README. |
| [OpenAI: Build skills](https://learn.chatgpt.com/docs/build-skills), How skills work; locations | Нативный skill требует своего SKILL.md и механизма обнаружения. Файлы `knowledge/procedures` здесь читаются явно, не объявлены нативными skills или hooks. |
| [OpenAI: Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), Better skills; AGENTS.md; Persistence | Точные триггеры, выборочное чтение, ясная граница завершения. Применены общие принципы; настройки модели и примеры из статьи не стали обязательными инструкциями проекта. |

Шесть запрошенных локальных файлов — `Codex Prompting Guide.txt`, `Model guidance _ OpenAI API.txt`, `Rethinking skills and prompts for GPT-6 Astra _ OpenAI Developers.txt`, `PromptGuide.txt`, `AgentsMD.txt`, `PersonalizeChatGpt.txt` — по именам в доступном репозитории не найдены; вложения с ними в этой сессии не предоставлены. Их чтение не заявляется. Одноимённая первичная веб-статья OpenAI прочитана отдельно.

Для справки по поведению хоста прочитан установленный навык openai-docs. Никаких новых plugins, облачных хранилищ, API-ключей, платных вызовов ради оценки стоимости или новых frameworks не добавлено. Три независимых контекста использованы для ограниченного автоматического ревью по прямому поручению пользователя; это не человеческая приёмка и не дополнительная постоянная часть продукта.

Для конкретного ремонта PDF дополнительно проверены первичные справки [PyMuPDF get_pdf_str](https://pymupdf.readthedocs.io/en/latest/functions.html#get_pdf_str) и [xref_set_key](https://pymupdf.readthedocs.io/en/latest/document.html#Document.xref_set_key). Выбран корректный Unicode PDF string для Filespec, а не процентное кодирование самого имени файла. Результат проверяется независимым pypdf и равенством отрисованных страниц.
