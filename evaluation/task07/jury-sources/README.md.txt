# Стратег Фабрики продуктов

Агент помогает руководителю цифрового продукта выбрать обоснованный следующий шаг: разобраться в документах и таблицах, проверить открытые источники, сравнить варианты и согласовать продуктовую стратегию, сообщение аудитории и план проверки. После выбора он сохраняет основания и обязательства, а при новых данных показывает, что требует пересмотра.

Начните с [материалов для жюри](submission/README.md): описание, учебный пример, настоящая запись работы и результаты проверок.

Работу ведёт уже авторизованный Codex с языковой моделью и инструментами. Python извлекает данные, считает и проверяет файлы. Это папка проекта с инструкциями и памятью, без отдельного серверного приложения и новых API-ключей.

## Запуск из архива

Нужны Windows, PowerShell, Python 3.12 и авторизованный Codex с правом работать в выбранной папке. Распакуйте архив «Проект.zip» в новую папку, откройте там PowerShell и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links third_party/wheels -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Закреплённые пакеты уже включены; сеть для установки Python-части не нужна. Активация PowerShell-скриптом не требуется. Для обращения к модели нужен действующий доступ Codex; для текущих сайтов — веб-инструмент. Происхождение пакетов указано в [реестре зависимостей](third_party/wheels/README.md).

Откройте эту папку в Codex. Поместите разрешённые материалы нового продукта в `projects/my-product/inputs` и напишите:

> Начни анализ проекта my-product. Помоги выбрать аудиторию и предложение по материалам в projects/my-product/inputs. Нужны продуктовая и коммуникационная стратегии и план проверки.

Далее достаточно обычных обращений:

- «Что готово и что требует моего решения?»
- «Остановись и сохрани место продолжения».
- В новом чате: «Продолжи анализ проекта my-product по сохранённому состоянию».
- «В новой версии таблицы изменились затраты. Проверь последствия и сохрани прежние основания».

Существующие демонстрации имеют собственную историю; начинать их импорт заново не нужно. [Продолжение в независимом контексте](evaluation/task07/continuation-review.md) проверено отдельно от установки Python.

## Что поддерживается

Документы DOCX и текстовые PDF, таблицы CSV/XLSX с явными диапазонами и единицами, датированные выдержки сайтов. Существенные выводы связаны с версиями источников и координатами. Сохраняются пять документов: ситуация, варианты, продуктовая стратегия, коммуникационная стратегия и план проверки.

После решения сохраняются исходные основания, ответственная роль, срок или условие, метрики и повод пересмотра. Новое свидетельство проходит проверку влияния: затронутые выводы меняются, остальные переиспользуются с объяснением. Это проверка при обращении, без фонового наблюдения и автоматической рассылки.

Один координатор пишет состояние проекта. Старые входы и результаты не перезаписываются. Повреждение показывается явно; восстановление предыдущей версии выполняется отдельно. Просьба остановиться позволяет сохранить безопасную границу, аварийное закрытие приложения этого не гарантирует.

## Проверка и ограничения

Проверить Python-часть самостоятельно:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 scripts/project_state.py load --project evaluation/task07/demo-workspace/projects/task06-rehearsal
```

Эти команды проверяют код и сохранённые файлы; модель самостоятельно запускается через Codex. Текст в PowerShell читайте с `-Encoding UTF8`. При отказе среды сохраните сообщение ошибки; не отключайте защитные настройки.

Учебные клиентские данные не доказывают спрос. Нет распознавания сканов, гарантии разбора любой PDF-вёрстки, нескольких одновременных писателей или разрешения тратить деньги и связываться с клиентами. Источники рассматриваются как данные, а не инструкции. Бизнес-решения принимает руководитель.

В комплекте передачи отдельный файл «Проверка.md» содержит результат проверки точного архива и его контрольную сумму. [Источники и технические проверки](submission/TECHNICAL_APPENDIX.md), [устройство инструментов](knowledge/tool-contracts.md) и [история разработки](docs/DEVELOPMENT_STATE.md) доступны отдельно.
