# План проверки — актуальная версия 2

Учебный синтетический пример; эксперимент не проводился. Пороги ниже предложены для согласования владельцем, не выданы за его решение. Исходный вариант v1 сохранён; RV1–RV4 исправлены.

**До запуска.** Проверить событие выполнения, уникального пользователя, правильное окно дней22–28 и канал регистрации. Тестовая коррекция S004@1 не доказывает реальную причину сбоя; при несопоставимой телеметрии сначала исправить измерение. Нужны оценка расходов и согласие владельца. [C009–C012]

**Гипотеза/сравнение.** Пакет «направляемый первый сценарий + ручная помощь» повышает D28 у новых recurring против обычного текущего продукта. Случайное назначение1:1 до воздействия; одновременный набор, фиксация канала и сегмента до назначения. Контроль получает обычную доступную всем поддержку, без дополнительного нейтрального контакта. Анализ intention-to-treat всех назначенных. Измеряется эффект всего пакета, включая внимание; перенос на автоматический onboarding потребует нового сравнения. Это устраняет неоднозначность активного контроля v1. [C001/C011/C012]

**Определения.** D28 = уникальные назначенные с ≥1 выполнением на днях22–28 / все назначенные с завершённым окном. Активация24ч = создали задачу за24ч / все назначенные с завершёнными24ч. Оплата30 = ≥1 оплата за первые30 суток / все назначенные с завершёнными30 сутками. Выручка30, возвраты30 и переменные расходы30 учитываются за те же30 суток; поздние возвраты записываются отдельно, окно не выдаётся за lifetime. Исторический «первый месяц» не переименовываем в30 суток: новый тест использует собственное заранее заданное окно. Затраты ручной помощи = минуты × фактическая ставка; распределение стоимости разработки/исследования фиксируется до запуска. Пропавшая телеметрия не равна нулю; при систематическом пропуске/дифференциальной потере результат неубедителен. [S001@1 body/b5/p4; плановые определения]

**Период/объём.** Первый этап: 4 недели набора +30 суток после последнего назначения, чтобы дозрели D28 и экономика30. При условном повторе сентябрьского потока100 recurring/месяц получится около50 в группе: это проверка осуществимости и крупного вреда; умеренный эффект10 п.п. может остаться неопределённым. Для более точной оценки предложены400 на группу:800 участников, примерно8 месяцев набора при том же неподтверждённом потоке +30 суток. Нормальное приближение для D28 около40–50% даёт погрешность разницы примерно7 п.п.; это ориентир точности, не гарантия мощности. Поток, минимальный эффект и объём пересчитать до запуска по реальным данным, не выбирать по удачному результату. Дедлайн конкурса не сокращает окно поведения. [C010; CALC-segments-v2 denominator; допущения планирования]

**Правила решения.** До запуска зафиксировать метод95% интервала разницы долей (например Newcombe/Wilson), критерии качества данных и стоимость вмешательства. Предлагаемая практическая цель +10 п.п. D28. Поддержка дальнейших инвестиций: точечный прирост≥10 п.п., нижняя95% граница>0, положительный дополнительный вклад по реальным затратам и приемлемый вред. Это допуск к следующей оценке, не доказательство эффекта минимум10 п.п. Неуспех для этой цели: верхняя граница<10 п.п. при достаточных данных либо устойчиво отрицательная дополнительная экономика. Перекрывающиеся/широкие интервалы, незрелые окна, плохие данные или неопределённая экономика → «неопределённо», не масштабировать.

Дополнительная экономика = `N_test×(paid_rate_test−paid_rate_control)×(price−v)−K_incremental` за одинаковые30 суток; при различии цены/затрат групп считать разность наблюдаемых выручки и расходов на сопоставимого назначенного пользователя. Исследовательские затраты показывать отдельно от потенциальной эксплуатации. Иллюстративный порог9 добавочных оплат на100 **получателей воздействия** относится только к C007; для50 получателей и того жеK2000 порог доли удваивается, поэтому его нельзя механически использовать в малом A/B.

**Вред.** Жалобы, навязчивый контакт, лишние задачи, возвраты и нагрузка поддержки. Каждый серьёзный инцидент разбирается сразу; при подтверждённом ущербе/утрате данных воздействие приостановить. Предлагаемый количественный сигнал пересмотра: доля жалоб в тесте выше контроля на≥5 п.п. после минимум50 наблюдений в каждой группе; это не статистическая гарантия безопасности. Контакты только с согласием, без персональных данных в репозитории.

**Следующее решение.** При пользе и экономике оценить автоматизацию и её отдельную проверку; при отсутствии эффекта исследовать повторную ценность/канал и сравнить keep/close по всей базе; при спросе на автоповтор проверить прототип против ручного процесса/существующей альтернативы. Расходы, реальный запуск и закрытие утверждает руководитель.
