# Стратег Фабрики продуктов

Агент помогает руководителю цифрового продукта перейти от размытого запроса к обоснованному следующему шагу: проверить документы и таблицы, сопоставить открытые источники, сравнить варианты и согласовать продуктовую и коммуникационную стратегии. После решения он сохраняет основания и обязательства, а при новых данных показывает, что нужно пересмотреть.

Ни одна из них не подтверждает спрос на RelayBox и не объявляется заменой непрочитанного дополнительного брифа организатора.

## Как устроена работа

Codex — среда с языковой моделью и доступными программными инструментами — выбирает вопросы исследования, проверяет основания и пишет рекомендации. Python извлекает данные из файлов, считает и проверяет сохранение. Постоянные инструкции, методы, материалы продукта и записи выполненной работы хранятся раздельно. Общую память проекта записывает один координатор. Отдельного сервера и новых API-ключей нет.

Результат включает пять документов: ситуацию, варианты, продуктовую стратегию, коммуникационную стратегию и план проверки. Существенные выводы связаны с версиями источников и точными местами в них. Старые входы и результаты сохраняются, бизнес-решение принимает руководитель.

## Запуск из репозитория или переносимого комплекта

Нужны Windows, PowerShell, Python 3.12 и действующий доступ к Codex с правом работать в папке. Скачайте доступную вам копию репозитория либо распакуйте «Проект.zip» в новую папку. Откройте PowerShell в её корне:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links third_party/wheels -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Три закреплённые зависимости включены; установка Python-части не требует сети. [Происхождение пакетов](third_party/wheels/README.md). Для самой модели нужен доступный лимит аккаунта Codex, для текущих сайтов — веб-инструмент. Фактические списания неизвестны, поэтому стоимость не названа нулевой.

Откройте папку в Codex, положите разрешённые материалы нового продукта в projects/my-product/inputs и напишите:

> Начни анализ проекта my-product. Помоги выбрать аудиторию и предложение по материалам в projects/my-product/inputs. Нужны продуктовая и коммуникационная стратегии и план проверки.

Можно уточнить: «Что требует моего решения?», «В новой таблице изменились затраты, проверь последствия», «Остановись и сохрани место продолжения».

**Новый чат без предыдущего диалога** означает отдельную беседу, которой не передают старую переписку. Она получает папку проекта и просьбу «Продолжи анализ проекта my-product по сохранённым файлам». Агент читает задачу, проверенную сводку и нужные источники; перед записью загружает полную сохранённую версию. [Такое продолжение текущего кода проверено на одном полезном аналитическом шаге](submission/CONTINUATION.md). Существующие демонстрации повторно импортировать не нужно.

## Границы и самостоятельная проверка

Поддерживаются DOCX, текстовые PDF, CSV, XLSX с заданными диапазонами и сохранённые выдержки сайтов. Нет распознавания сканов, гарантии чтения любой PDF-вёрстки, фонового наблюдения, автоматической рассылки и нескольких одновременных писателей. Проверка обязательств выполняется по обращению. Повреждение файлов показывается явно; аварийное закрытие не гарантирует сохранение.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 scripts/project_state.py load --project evaluation/public-data-release/projects/uci-shoppers --summary
```

Эти команды проверяют программу и сохранённые файлы; они не запускают новое исследование языковой моделью. В PowerShell читайте русский текст с параметром -Encoding UTF8.
